## Observable outcome and existing owners

For a record with at least two witnessed signatures and a complete injected set
of exact authored cues, Gallery presents a visible vertical register. Selection
immediately republishes that exact record projection without starting Replay or
writing Profile. Known witness chronology and the separately unordered legacy
partition retain the order supplied by the existing owner.

GalleryScene retains selection, Retry and departure. GalleryReplayOwner retains
replay admission/lifetime. GalleryRecordCatalog supplies exact cue/projection
copy. GalleryRecordPaper remains the sole record-scroll owner. The register
reuses GalleryRecordButton input/state behavior with paper widths and roles;
the index defaults remain unchanged. There is no new save, recovery, History,
chronology or metadata owner, and no write-only duplicate selected-ID field.

## Bounded behavior

- Zero/single versions reserve no register heading, rows, focus group or extent.
- Exact row objects survive locale changes, reprojection and newest insertion.
- Tab visits all version rows; Right visits the selected version between optional
  overflowing Record details and Replay. Up/Down clamp; Left returns to the record.
- Pointer hover/hold are inert; release selects, outside release cancels, and
  double-click continuation starts no extra command. D-pad navigation restores
  visible focus. Injected ScreenDrag routes to Paper and cancels the pending press.
- Same-version activation retains Retry; a different version clears it. Retry
  reuses the exact failed signature. Only Replay starts playback.
- Paper reveals nested rows using body-relative coordinates. Layout corrections
  also handle redistributed row heights with unchanged total extent. Oversized
  cues preserve a stable visible interior; they cannot fit wholly at once.

## Production-content boundary

Production exact cues remain absent. If any exact cue is missing, the existing
dropdown and Replay availability remain in place. This prevents missing authored
content from revoking previously available replay, and avoids invented labels or
hidden-field leakage. This is fixture-backed register engineering, not a final
production-content cutover. General sentences are not substitute version cues.

## Limits and remaining work

The renderer uses real Gallery/Profile owners, explicit noncanonical TEST copy,
in-memory FileOps, software OpenGL and injected Viewport input. It does not prove
native OS keyboard/touch, UIA, Windows ScrollPattern, final story translations,
production cue completeness, or the full Gallery release contract. The drag
check is injected-event cancellation/routing, not a complete physical touch chain.

The History notice is not merely missing copy: current replay completion carries
no durable merged-line result. A later bounded implementation must collect valid,
actually presented session-bound lines and compose the existing Profile atomic
commit owner, then announce only a proven newly durable addition. Do not publish
a notice from playback completion alone or add a second History store/recovery
framework. The current UI change does not perform such a merge.

`dwm-7wj` remains in progress. No Bead is closed; committed export notes do not
claim live Dolt synchronization. The records-only descendant is not independently
engine-tested and does not introduce additional runtime changes.
