## Connected behavior observed

board and existing persistence owners perform this sequence:

1. Publish two pre-challenge captions; open and close inspect-only History.
2. Complete pre-prose naturally, enter the board and commit an actual terminal loss.
3. Publish post-prose; press F5 during partial reveal without advancing the semantic
   line, inspect History, cancel real F9 Load confirmation and commit manual Save.
4. Advance the live post-line; refuse an older prepared Save while preserving the
   accepted Quick bytes and newer live frontier.
5. Start a fresh process in the same proven isolated user root. Use ordinary
   Backup prepare/commit Load to restore the saved stable line, all three captions,
   both immutable entry frames and committed physical result.
6. Restore the saved line fully visible with read-aloud enabled and zero repeated
   speech admissions. History inspection adds no gameplay/completion/witness effects.
