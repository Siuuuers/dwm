# Restored ending aggregate checker

`check_restored_profiles.py` is offline metric analysis, additive to the existing source/custody, two-case census, clean-exit, save/history and durable-completion review. A metric pass alone does not qualify the journey. The caller must retain `extract_raw(log)` before calling `validate_log(log, loader_pid)`; the CLI does so automatically and writes a failed result if validation fails.

The checker requires nine ordered capture/prepare/commit aggregates inside the three matching writer intervals within the final Accept interval. It validates the current exact observer schema, same-PID monotonic phase markers, successful dynamic samples, complete snapshots and inclusive arithmetic. Capture can be empty; configuration/compilation can have zero samples. Nested categories overlap and must not be summed as exclusive costs. The reviewed wrappers do not recursively invoke the same sample kind on this successful path; leaf totals may therefore be bounded by their enclosing scope.

Run offline checks with `python -m unittest -v test_restored_profiles.py` from this directory. The test fixture contains nine original aggregate JSON payload strings extracted without modifying their contents from run39759857757, artifact12417991127, `phase2r_logs/ending-layout-boundary.log`. Original log SHA256: `6d62052c609323705df5f8d9e50d557735a3d8afb76606bb74f247a7e119a5c0`. Fixture SHA256: `15a346a592bc9f8c1e22caa343f742525c3106314654be70b3010be567ebccae`.

Tests put these real **short-route** records into **synthetic restored-route marker envelopes**. This establishes checker behavior only, not a restored-route profile result or new gameplay evidence. Tests include absent/extra/malformed records, duplicate JSON keys, failed observations, numeric types, invalid labels, missing returns, wrong PID/order/association, nesting and empty capture.
