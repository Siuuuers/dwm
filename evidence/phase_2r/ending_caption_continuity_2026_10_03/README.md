# Bounded ending caption continuity

To reconstruct the archives referenced by the receipt, run from this directory:

```sh
python restore_archives.py --output /tmp/ending-caption-evidence
```

`archive-delivery.json` maps every original ZIP to compressed, bounded transport
parts. The helper verifies each part, the compressed stream and the reconstructed
ZIP against SHA-256. Existing different output files are refused. This packaging
avoids upload-transport truncation; it does not alter the cloud evidence bytes.

The source-bound `receipt.json` records the acceptance boundary. Cloud artifact
manifests retain GitHub IDs and SHA-256 digests. Direct cloud archives preserve
the original downloaded bytes; regression/history bundles contain those original
ZIPs as unchanged members. XML totals count primary reports, excluding intentional refusal
controls. Diagnostic failures remain diagnostic, not passing evidence.

The observable outcome is that the last two witnessed caption leaves remain
visible across the fixture's physical ending boundary, and a fresh Load reconstructs
the same visible window without replaying earlier consequences. The existing
semantic ledger owns history; the mounted caption layer owns only its ephemeral
projection. Native handoff retention is explicitly opted in and generation-bound.
No durable caption store, save schema or alternative completion owner is added.

The rendered archive contains raw post-draw observations, screenshots, process
reports, exact save bytes and the writer seal. Observations check actual mounted
node text, order, visibility, opacity, reveal and viewport containment. The fixture
uses short noncanonical captions and seeded ending eligibility. This is not a
claim about all production routes, long-caption geometry, Auto continuity, every
input device, native Windows accessibility, OS-crash behavior or performance.

Actions. Local work was source review and artifact inspection. Production caption
