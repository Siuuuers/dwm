# Backup revision storage verification

Run `python tests/backup_storage/verify.py` from the isolated worktree. The runner copies the actual storage sources, tests and GUT into a disposable project under `.godot/backup-storage-*`, with no game autoloads and isolated application directories. Every storage operation uses FakeFileOps. The receipt records SHA-256 of every copied source; the full log retains diagnostics.

The new API uses exact raw SHA-256 revisions and the sentinel `absent`. `inspect_revision` only reads: no reconciliation, mutation or playable lease. An unreadable encoding returns `text: null` with its raw revision. A zero-byte file has the standard empty SHA-256, distinct from absence. Pending marker, candidate or opaque-prior artifacts, and an orphan backup, refuse inspection and revision mutations.

Confirmed writes and deletes use a closed v2 marker at the existing `.txn.json` path. The immutable marker binds the relative path, operation, prior raw hash, existing backup raw hash and outgoing hash. The `.revision-prior` sidecar is temporary rollback custody only; its bytes are never admitted as a playable save. Outgoing candidates and the final winner must pass the supplied real validator. Recovery accepts only the marker's exact artifact hashes, rechecks the durable marker during mutation and cleanup, and retains unbound or torn evidence as indeterminate. Writes without a surviving candidate restore exact prior bytes without granting a lease. Successful revision writes remove the bound prior and backup; v1 writes retain their existing `keep_backup` behavior.

The suite covers valid, invalid JSON, future-shaped, invalid UTF-8, empty, absent and unchanged records; existing backup custody; stale confirmation; rejected outgoing data; unknown and torn families; foreign final/candidate/prior/backup hashes; malformed markers; a validator callback replacing the durable marker; each fallible I/O position in representative writes/deletes; and restart from every persisted operation boundary. The original eight GUT storage tests also run unchanged.

Verified receipt: `.godot/backup-storage-b4yvlnka/result.json` — 1,644 assertions, 578 injected operation positions, 703 restart snapshots, and original GUT 8/8. This proves the FakeFileOps transaction model, not physical power-loss durability or concurrent external filesystem writers. Existing FileOps rename/flush assumptions remain. Torn writes are preserved as unavailable evidence rather than promoted. Expected logs include deliberate malformed UTF-8 decoding diagnostics, the inherited literal NUL diagnostic and the sandbox's unavailable certificate store; they are disclosed, not described as a clean log.
