# Exact caption witnessing: bounded engineering record

Updated 1 October 2026, 18:23 UTC (2 October, 02:23 Hong Kong).

This record describes the prerequisite to one-shot Next in `dwm-vky.14`. It does not approve production prose, close the broader reading rail or authored-selector tasks, or replace the [Witnessed scene contract](../design/current-ui/witnessed-scene.md). Cloud acceptance and immutable source identities belong in the live handoff and retained evidence receipt.

## Identity and scope

The opt-in, fixed English Solo fixture supplies one registered descriptor for each visible caption: `beat_id`, `line_id`, `owning_entry_id`, and its complete `presentation_signature`. The existing fixture compiler declares `content_revision` and `variant_id`; it does not infer selectors from mutable gameplay. The same descriptor in a new Run/attempt remains the same exact variant. A changed declared revision or variant is unseen even when its stable line ID has been visited.

Run, branch, attempt, playback, publication and transaction IDs establish current-source custody. They do not enter the durable witness key. Neither the whole catalogue fingerprint nor the complete frozen gameplay context is a prose-variant key. The catalogue fingerprint continues to govern Run checkpoint compatibility independently.

This finite fixed-prose contract does not implement a general authored branch resolver. Production catalogue registration remains disabled. Future production registrations must account for every independently authored wording/staging selector before claiming exact coverage. Existing unqualified narrative and Rehearsal owners retain their prior behavior; reached/Gallery membership is separate from caption witnessing.

## Profile ownership

Profile v10 adds `witnessed_caption_variants`, keyed by the SHA-256 of canonical descriptor bytes and retaining the complete detached descriptor. Validation recomputes each key and requires the accompanying base-line visit. An exact witness and its base-line visit commit together through the existing Profile atomic writer. Base-line membership never backfills exact credit.

The retained migration paths, including v9, initialize exact membership empty. This optional engineering choice preserves truthful old history without inventing exact witnesses; it does not reinstate mandatory support for obsolete development formats.

Ordinary prepared commits and supported-format restoration cannot remove existing exact witnesses. Clear Visited History and full Profile reset are the explicit removal paths. Settings changes, Clear Gallery, New Run and loading an older Run preserve current Profile witnesses. Transaction rollback retains its existing compensation role.

## Visible publication and transport

DialogicBridge uses the current admitted Solo occurrence at the existing visible-line acknowledgement seam. Catalogue registration, caption-ledger capture, History inspection and capability queries are not witness events. A caller cannot select another catalogue row as the displayed line.

The acknowledgement retains the witnessed status from before the first Profile write. Recording a new visible variant must not let the same Read Only activation pass through it. Source replacement, Pause, reentrancy, recoverable write refusal and indeterminate persistence retain the existing custody and retry rules. An idempotent witness operation still checks mutation custody and the fatal latch.

Next remains disabled in this increment. Its later traversal must consume the exact witness predicate and the retained pre-publication baseline, while reusing the existing physical challenge/completion owners.
