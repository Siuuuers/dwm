# Rendered F5 baseline, 2026-11-04

A bounded observation of the existing Save-sheet F5 operation. No performance
change was implemented. [Raw samples and diagnostic events](../../evidence/performance/f5-2026-11-04/baseline.json)
retain microsecond values, source hashes, log hashes and excluded attempts.

## Result

Six sequential fresh-process samples passed the existing benchmark's durable-save,
unchanged-reading and unchanged-gameplay checks: 25 assertions per first-save sample and 28 per fourth-save sample
(159 total).
Three measure the first Save; three measure the fourth Save at the same reading
position. Profiling was disabled for these six samples.

| Median, milliseconds | First Save | Fourth Save |
| --- | ---: | ---: |
| Input dispatch | 44.352 | 43.013 |
| Input to Saved draw | 53.880 | 52.556 |
| Input to completed rendered frame | 67.175 | 64.821 |
| Maximum process-frame gap in measured window | 68.620 | 65.915 |
| Capture callback inclusive work | 1.119 | 1.242 |

Completed-frame ranges were 64.530–78.918 ms and 63.396–82.101 ms respectively.
Each sample captured six times, with one reading-history entry, no recovery-journal
entries and a 4,601-byte quicksave. Fourth Save does not mean longer history.
Three samples per case do not establish tail latency or a platform-wide guarantee.

One separate profiler-enabled diagnostic reported preparation at 14.553 ms
(including capture phase 10.100 ms) and commit at 16.470 ms (including atomic write
6.172 ms, journal commit 3.744 ms and source recheck 3.252 ms). These scopes are
nested/inclusive and must not be summed. They identify investigation targets,
not proof of redundant work or permission to remove validation/data-loss handling.

## Reproduction

Starting checkout HEAD was `8eeac7ceee26f787136689f76b45a83e54f7ac1a`.
Another worker concurrently removed dormant DatingScene draw helpers; this worker
made no source edits. The three captured source hashes (benchmark, SaveManager,
BackupPresentationPort) were collected after execution and verified identical to
that starting revision. No per-process full-tree hash was captured, so this is
not an immutable-tree performance certification. Other workers also changed CI
workflow files; those files are not executed by this local benchmark. The benchmark exercises the
short scene-reading/Save fixture, not the DatingScene challenge journey.

Use installed Godot 4.6.3 and Xvfb with the existing import cache. For repetitions
0–2, run `fresh` then `repeated`, sequentially. Set a new label/storage directory
for every process; preserve the same runner and settings:

```bash
export DWM_F5_CASE=fresh DWM_F5_PROFILE=0 LIBGL_ALWAYS_SOFTWARE=1
export DWM_TEST_ROOT="$PWD/.godot/phase2r_tests/profile-next/fresh-sample-0/test-root"
export XDG_DATA_HOME=/tmp/dwm-profile-next/fresh-sample-0/data
export APPDATA=/tmp/dwm-profile-next/fresh-sample-0/appdata
export LOCALAPPDATA=/tmp/dwm-profile-next/fresh-sample-0/local
/tmp/dwm-tools/bin/xvfb-run -a -s '-screen 0 1920x1080x24' \
  /tmp/dwm-tools/Godot_v4.6.3-stable_linux.x86_64 --path . \
  --rendering-method gl_compatibility --rendering-driver opengl3 \
  --audio-driver Dummy -s res://addons/gut/gut_cmdln.gd -gconfig= \
  -gtest=res://tests/manual/benchmark_f5_save_latency.gd -gexit -glog=1
```

The local Xvfb wrapper creates a fresh virtual display and invokes Godot over X11;
it is an environment utility, not a new repository dependency. Its output is Mesa
llvmpipe software rendering. No faults were armed. The diagnostic uses the same
command with `DWM_F5_PROFILE=1` and separate storage, excluded from baseline medians.

## Limits and excluded attempts

This is Linux software rendering, not native Windows, physical display latency,
full authored-week content or long-history performance. Logs include missing
libspeechd, unsupported VSync and exit ObjectDB/resource warnings; no script errors
occurred in accepted samples. Do not compare absolute timings against another
runner or claim that preceding dead-code deletions caused a speedup.

Three setup attempts produced no accepted timing: an outside-project test root
selected final Bootstrap and caused registration conflict; a bundled-library
override caused a native abort; GUT rejected an explicit bootstrap argument.
The subsequent successful feasibility run is also outside the six-sample batch.
The raw evidence identifies each excluded log.

Next: inspect the preparation/capture and commit ownership for concrete repeated
work. Only implement an optimization after identifying its cause, then compare
baseline/candidate complete operations on the same runner in alternating order.
