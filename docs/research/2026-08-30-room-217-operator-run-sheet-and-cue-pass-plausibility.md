# Room 2.17 operator run sheet and cue-pass plausibility

Date: 2026-08-30 \
Sources accessed: 2026-08-30 \
Status: **NONCANONICAL RESEARCH.** This note does not amend canon, place Room
2.17 on Day 2 or Day 6, approve a Group adaptation, authorize dialogue, assign
East Harbour institutional powers, or select public-event equipment.

## Scope and reading rule

This note checks a narrow physical and institutional question: can a small
university event-preparation meeting credibly bring together a
programme/communications coordinator, a conservatory performer with input into
the presentation of her item, and the assigned astronomy demonstration
operator, using a modest run sheet and a bounded operator pass?

**Verified general practice** means an official university, conservatoire,
theatre-department, NASA/JPL, or equipment/software source describes the
practice. **Project inference** means a conservative implication drawn from
those sources. **Recommended fictional staging** is one workable Room 2.17
choice, not something the sources require. East Harbour's titles, authority
lines, room rules, and exact event remain fictional.

## Bottom line

**Keep the pass small, but give Angela one real source state to operate.**

1. **Run sheet: yes, with a qualification.** Official university event guides
   use chronological run sheets/run-of-show documents, and official production
   guides use ordered cue sheets or cue plots. Sequence, responsible role,
   action, notes/warnings, and contingency information are all ordinary. A
   university-published one-page template demonstrates the lightweight form,
   but neither one page nor this project's exact column set is a universal
   standard.
2. **Small preparation room: yes, for a bounded pass.** Paper tech occurs before
   full technical integration, dry tech can omit performers, and cue-to-cue
   work skips material that is not needed for the cue. A desk-level planning or
   local-source acceptance pass can therefore occur away from the final venue.
   Calling it a complete technical rehearsal or full cue-to-cue would overstate
   what it proves.
3. **Minimum source state:** one run sheet, one laptop or comparable local
   display device, one fixed local source package, two explicit orders, and a
   holding/reset state. The operator must actually execute both orders. No
   projector, telescope, network connection, stage, shared audience route, or
   exact public handoff is needed to test local source order and reset behavior.
4. **The pass proves only bounded operability.** It cannot prove public
   visibility, acoustics, telescope alignment, projection, venue power,
   network reliability, visitor circulation, performer spacing, safety, or
   exact live timing. Those require later checks with the relevant people,
   equipment, and space.

## 1. The lightweight artifact is normal practice

### Verified general practice

Simon Fraser University's Ceremonies and Events toolkit defines a detailed
programme schedule—also called an event run-down, **run sheet**, or run of
show—as a complete chronological sequence of event tasks. It says the document
should cover times, AV, entertainment, speakers, programme activity, and staff
roles and responsibilities. [SFU, *Day-of
planning*](https://www.sfu.ca/ceremonies/toolkit/planning/day-of-planning.html)

Charles Darwin University publishes a one-page `Event Run Sheet` template with
event name/date/location fields and the columns `TIME`, `TASK`,
`RESPONSIBILITY`, and `NOTES`. This is direct first-party evidence for a small,
printable artifact; cue numbers, operator commands, and a dedicated contingency
column would be local adaptations rather than CDU requirements. [CDU, *Student
Group Event Run Sheet
Template*](https://www.cdu.edu.au/files/2020-07/Event%20Run%20Sheet_Template.docx)

SFU's more technical execution guidance keeps the programme schedule, AV show
flow, contact list, floor plan, script, and attendance materials as separate
day-of documents. Its official show-flow template uses numbered rows with
time/source/cue fields and operator actions such as on, off, pause, and loop.
That separation supports a dedicated operator sheet without forcing audience
routing or a full venue plan onto the same page. [SFU, *Execution*, “Day-of
event documents” and “AV
briefing”](https://www.sfu.ca/ceremonies/toolkit/execution.html) and [official
Show Flow
template](https://www.sfu.ca/content/sfu/ceremonies/toolkit/downloads/_jcr_content/main_content/download_14/file.res/Show-Flow-Template.docx)

The University of Nebraska Omaha's communications event checklist applies its
planning advice to events “whether big or small.” Its run-of-show master
document contains an item-by-item sequence and a detailed outline of what each
person should do and when. The same guide asks organisers to identify roles,
allocate tasks, confirm rehearsal timing, and provide emergency contacts and
backup plans. [UNO, *Communicator's Toolkit: Event Planning Checklist*, pp.
2 and 8–10](https://www.unomaha.edu/office-of-strategic-marketing-and-communications/_files/communicators-toolkit/toolkit-eventplancheck-0225.pdf)

The Royal Conservatoire of Scotland's production glossary defines a **cue
sheet** as a list of cues in the correct execution order, and cue-to-cue as a
technical rehearsal that works through cues, often skipping parts of the
script. [RCS, *Scenic Production Handbook*, glossary entries “Cue Sheet” and
“Cue-to-cue”](https://paperclip.rcs.ac.uk/images/d/d7/Scenic_Production_Handbook_for_Paperclip.pdf)

The University of Alaska Fairbanks Theatre & Film handbook says cue plots are
normally tables containing a cue number or label, script reference or timing,
description and timing, and notes or warnings. It also says the documentation
should be organized by department or function, easy to read, update, and
share, and usable for real-time calling. [UAF, *Stage Manager's Handbook*,
§§7.2–7.3](https://www.uaf.edu/theatrefilm/stage-managers-handbook.php)

The Centre for Research into Energy Demand Solutions' first-party account of a
university-led event uses a running order with `Time`, `Activity`, and `Actions`
and assigns named people to day-of tasks. It also describes the document as a
contingency aid: a replacement can use it to take over an absent person's role,
and deputies are assigned for critical functions. [CREDS, *Creating a running
order for a hybrid
event*](https://www.creds.ac.uk/creating-a-running-order-for-a-hybrid-event/)

SUNY New Paltz notes that a paper-tech meeting can sometimes be replaced by
shared information or a digital script. The artifact therefore need not be
literal paper even when the production term is “paper tech.” [SUNY New Paltz,
*Production Handbook*, “Paper
Tech”](https://www.newpaltz.edu/fpa/theatre/productions/production-handbook/)

### Project inference

The proposed Room 2.17 fields are a conservative combination of documented
practices:

| Proposed field | Primary-source support | Boundary |

| Cue/source ID and relative order | RCS ordered cue sheet; UAF cue label and reference; SFU show flow | Verified general practice |
| Responsible role | CDU responsibility field; SFU and UNO staff responsibilities; UAF department/function | Verified general practice |

For a bounded four-to-eight-cue check, fitting those fields on one page is
physically and administratively plausible. Page count, typography, whether the
master is printed, and whether handwriting is permitted are institution-specific
choices.

## 2. What a small-room pass can and cannot be

### Verified general practice

UAF separates successive levels of production work:

- **Paper tech** walks through the script, establishes preliminary cue
  placement, transitions, and technical needs, and identifies challenges
  before entering the performance space.
- **Dry tech** tests and troubleshoots technical elements without performers.
- **Cue-to-cue** moves from one technical moment to the next, skipping
  non-technical sections; performers attend as needed.
- **Wet tech** integrates performers and technical elements, adding performance
  timing, spacing, and safety.
- **Dress rehearsal** is the full run with the remaining production elements.

[UAF, *Stage Manager's Handbook*,
§7.1](https://www.uaf.edu/theatrefilm/stage-managers-handbook.php)

SUNY New Paltz similarly describes paper tech as establishing cue numbers,
content, rough levels, and rough timings before technical rehearsals; dry tech
normally trains crew without actors; and cue-to-cue develops timing and
accuracy by rehearsing only what each cue needs. It also cautions that a
cue-to-cue tends to bring the production's technical elements together. [SUNY
New Paltz, *Production Handbook*, “Technical Rehearsals” through “Cue to
Cue”](https://www.newpaltz.edu/fpa/theatre/productions/production-handbook/)

### Project inference

A small, safely occupied preparation room is compatible with the **paper-tech
and desktop-operator** level of this progression. Room 2.17 does not need a
stage merely to compare an annotated sequence and operate locally stored
sources. Three people can perform the bounded task at a desk without Lavinia
dancing her item or Angela operating public observing hardware.

The accurate internal name would be **operator cue pass**, **desktop acceptance
pass**, or **paper-tech/source check**. `Cue-to-cue-style` is defensible as a
description of skipping straight between cue states. `Full cue-to-cue`, `full
tech`, `dress rehearsal`, or `venue acceptance` would not be supported without
the relevant live elements.

| The Room 2.17 pass can test | It cannot test |
| --- | --- |
| Whether both orders are unambiguous on the sheet | Audience comprehension or preference |
| Whether the assigned operator can open, advance, reverse, and reset the local sources in either order | Projector brightness, colour, aspect ratio, sightlines, or screen placement |
| Whether cue IDs match the intended local files/states | Telescope alignment, tracking, focus, observing conditions, or solar safety |
| Whether a missing/broken local source produces the stated fallback or a clear failure | Venue power, Wi-Fi, audio reinforcement, radios, or front-of-house communication |
| Which downstream document entries depend on the selected order | Visitor route, shared audience, cross-building travel, or a literal performance-to-astronomy handoff |
| Bounded source-transition operability | Exact public timing, performer spacing, movement safety, or full-show integration |

## 3. Minimum equipment and source state

### Verified general practice

NASA's Night Sky Network explicitly offers downloadable PowerPoint astronomy
presentations for meetings, class visits, **inside venues**, and cloudy days. It
suggests using them after safely stashing the telescope when weather prevents
sky viewing, and permits modification and sharing with the requested credits.
This establishes that an astronomy outreach item can have a legitimate
downloaded, slide-based source state that is not a live telescope feed. [NASA
Night Sky Network, *List of Ready-Made Presentations for Meetings, Class Visits,
and Cloudy Days*](https://nightsky.jpl.nasa.gov/news/208/)

NASA's Roman community-event package provides the same outreach material in
downloadable Keynote, PowerPoint, PDF-with-script, and JPG-ZIP forms. This is a
first-party example of a versioned astronomy presentation being available as
both an editable deck and flattened local fallbacks. [NASA Science, *Roman
Community Events
Files*](https://science.nasa.gov/mission/roman-space-telescope/roman-community-events-files/)

As one documented implementation rather than a required brand, Microsoft says
PowerPoint presentations can be saved to a laptop's local drive, slides can be
rearranged in the thumbnail pane or Slide Sorter, and a show can be played from
the beginning, current slide, or a custom sequence. [Microsoft, *Save your
presentation file*](https://support.microsoft.com/en-US/PowerPoint/save-your-presentation-file),
[*Add, rearrange, duplicate, and delete
slides*](https://support.microsoft.com/en-us/office/add-rearrange-duplicate-and-delete-slides-in-powerpoint-e35a232d-3fd0-4ee1-abee-d7d4d6da92fc),
and [*Present your slide
show*](https://support.microsoft.com/en-US/PowerPoint/present-your-slide-show)

### Recommended fictional staging

The smallest concrete setup that makes Angela's judgment real without creating
a public handoff is:

1. **One one-page internal run sheet.** Its header identifies the source-pack
   version and says `INTERNAL OPERATOR CHECK`; it uses relative cue order, not
   public clock times.
2. **One battery-capable laptop or comparable local display.** Its built-in
   screen is enough. The relevant viewer and files are already local; the scene
   does not need to establish room Wi-Fi, a projector, a cable standard, or a
   wall socket.
3. **One fixed local source pack.** At minimum it contains a neutral holding
   state and two stable, named operator-visible states, here called `SRC-A` and
   `SRC-B`. They may be two slides or still images. Their actual astronomy
   subject and provenance remain unselected.
4. **Two inspectable orders using the same source states.** Priscilla's typed
   order can read `HOLD -> SRC-A -> SRC-B -> HOLD`. Lavinia's already-present
   pencil arrows or renumbering can unambiguously read
   `HOLD -> SRC-B -> SRC-A -> HOLD`. Stable source IDs keep the typed order and
   the marked alternative simultaneously inspectable; two separately printed
   manifests are unnecessary.
5. **One reset and one local contingency.** Angela runs the typed order, returns
   to `HOLD`, then runs the marked order. A flattened local PDF/JPG copy may be
   the file-open fallback; alternatively, `stop, mark failed, return to source
   brief` is a valid contingency if substitution is not permitted.

`SRC-A` and `SRC-B` are deliberately acceptance-test placeholders. Because the
sequence is a local demonstration-side source block rather than two public
programme sessions, their reversal asserts no shared audience, adjacent venue,
visitor route, or live handoff from Lavinia's performance to Angela's astronomy
demonstration.

The source pack must actually be open and operated if `Either` is to report
**operability**. A paper-only comparison can establish that both written orders
are legible, but it cannot establish that both source transitions execute. At
least one operator-visible transition must change between the two orders. If
Angela's action is identical in both and only prose outside her responsibility
moves, her technical judgment has no demonstrated object.

Both tests should hold hardware, source files, cue IDs, and success criteria
constant so that order is the only changed variable. The minimum pass criterion
is narrow: each named state opens in the specified sequence, the transition is
callable, reset returns to the known holding state, and the stated local failure
path is intelligible. Passing does not mean the two orders are aesthetically
equal or equally preferred.

## 4. Fictional choices that still require owner approval

The primary sources establish general practice, not East Harbour facts. The
following remain creative/institutional decisions:

- whether Room 2.17 is used on Day 2 or Day 6, its capacity, furniture, booking
  rules, and whether the three characters may use it unattended;
- Priscilla's exact title, authority to issue the internal sheet, and ownership
  of the resulting version;
- Lavinia's exact authority over her item, why her presentation judgment
  changes these operator-facing source states, and whether a pencil mark is an
  institutionally accepted revision method;
- Angela's assignment, qualification, device access, and the exact bounded
  question she is authorized to answer;
- what `SRC-A` and `SRC-B` depict, who created or approved them, their credits
  and licences, and whether a deck, still-image viewer, PDF, or other local tool
  is used;
- whether the institution supplies a laptop and whether it is charged; the
  recommendation deliberately does not establish room power or network access;
- the sheet's exact rows, typography, contingency wording, version number,
  clock times, and whether it is printed, digital, or printed from a digital
  master;
- the exact invitation, prompt, blocking, dialogue, pause length, and action
  surrounding the marked-order decision;
- any public venue, projector, telescope, observing target, weather condition,
  audience, route, handoff, or rehearsal schedule; and
- any claim that this desktop pass completes public technical approval or that
  Angela's finding evaluates Priscilla, Lavinia, their relationship, or the
  artistic merit of either order.

The sources also do not establish that a conservatory student has unilateral
control over programme order or that a student astronomy operator has
cross-department approval power. Those are plausible local assignments only
after the fiction defines them. The safer characterization is that Lavinia owns
the marked presentation judgment, Angela reports the assigned operator fact,
and Priscilla owns the internal document update.

## Conclusion

Room 2.17 needs no invented stage infrastructure. A one-page shared run sheet
with Priscilla's typed order and Lavinia's clear pencil reordering, plus one
laptop already holding a fixed local source pack, is sufficient for a genuine
bounded operator pass. Angela should run both source sequences and reset
between them. That supports a finding that either order is technically usable
for this small test—and nothing more.
