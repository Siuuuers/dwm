## 2. Current product character, scope, and non-goals

Gallery is one maintained campus microfiche registrar: a narrow
controlled-dark discovered-record index beside a larger Worn-Cream record desk,
with one pinned action dock. It is an application, not a simulated file manager,
card catalogue, achievement cabinet, projector, or corrupted terminal.

The private design covenant is:

> The registrar files only what happened; the unbuilt annex leaves no missing
> door.

That sentence is never visible, assistive, localized, or tutorial copy.

Gallery presents public evidence already owned elsewhere:

- personal first-discovery order;
- a registered authored title and one authored sentence;
- optional registered public media;
- exact witnessed versions only when more than one exists;
- truthful Replay availability;
- a proven visited-History merge result; and
- truthful technical refusal or failure.

It never explains what an ending means, reveals why a route happened, identifies
an undisclosed participant or speaker, assigns a semantic class, exposes a
completion denominator, or supplies a decoding key. Record and version
selection are archive inspection, and Replay is an ordinary software command.
They are not selectable story choices. Minesweeper results remain the sole
choice-like narrative agency under their own authority.

### 2.1 Current-v1 Endings-only boundary

Current Gallery contains Endings only. Because the shell already says Gallery
and no current peer register exists, Gallery adds no local `Endings` heading.

The complete Rehearsal function is future-only. Current Gallery contains no:

- Rehearsal label, mode bar, reserved gap, disabled key, hidden key, unlock
  hint, mystery symbol, or mode-shaped absence;
- Scenes or Full Dates heading, facet, facet sheet, reached-record projection,
  `Begin Rehearsal` action, sandbox, or result selector;
- Rehearsal Focus stop, assistive node, tooltip, icon, localization key, asset
  slot, empty-state reference, or test fixture;
- first-ending milestone consumer, seed reader, profile/save field, migration,
  session owner, recovery branch, or compatibility path; or
- geometric, semantic, architectural, or implementation scaffold.

The existing milestone does not manufacture current UI. D alone preserves the
future direction and reopening conditions.

### 2.2 Current scope

This dossier closes only:

## 3. Vocabulary, ownership, and state partition

### 3.1 Exact Gallery terms

- **Discovered record:** one public projection for a durably discovered
  semantic ending identity. The UI receives an immutable public record and an
  opaque receipt reference, not hidden signature fields.
- **Personal order:** ascending durable first-discovery sequence of currently
  discovered identities. The sequence number is never displayed.
- **Exact witnessed version:** one compatible canonically reached presentation
  signature exposed through an authored public cue. Hashes and hidden field
  lists remain private.
- **Selected record:** the one discovered row whose paper is projected. It is
  presentation state only.
- **Selected version:** the one exact witnessed version projected for the
  selected record. It starts nothing.
- **Record details:** the record-paper semantic scroll region that exists only
  when real content exceeds its viewport. It is never a button.
- **Registered media:** optional immutable public art bound by a semantic
  manifest. It is decorative evidence and never grants discovery or Replay.
- **Replay:** the sole Gallery action that asks the external replay resolver to
  prepare the exact selected record and version.
- **Gallery view cache:** record/version identity, both scroll offsets, and
  meaningful Focus retained only across one direct Replay round trip.
- **Visible custody:** the static dock seam shown only when a genuinely admitted
  handoff remains unresolved across visible frames.
- **Information status:** one factual dock result, either `Unavailable` or
  `New dialogue added to History`.
- **Unavailable record:** one discovered record whose required public projection
  cannot be trusted. It remains in personal order but cannot Replay.

## 4. Exact current-v1 native mounting

### 4.1 Coordinate contract

Geometry is authored on the exact 640×360 native master and displayed at 2:1 on
the 1280×720 logical canvas. One native pixel equals two logical pixels. All
rectangles below are Gallery-host-local native coordinates unless explicitly
stated otherwise.

The shell provides a 480×328 host. Gallery owns:

| Region | Native rectangle |
|---|---|
| Gallery host | `(0,0,480,328)` |
| current Endings body | `(8,8,464,312)` |
| index | `(8,8,172,312)` |
| exposed-habitat gutter | `(180,8,8,312)` |
| record desk | `(188,8,284,312)` |
| record paper | `(188,8,284,272)` |
| pinned dock | `(188,280,284,40)` |

Width closes as 172 + 8 + 284 = 464. Height closes as 272 + 40 = 312.
The gutter is bare habitat. It is never a divider, seam, scroll well, Focus
target, assistive node, or encoded missing register.

Gallery adds no local title, clock, Return, window frame, close button, mode
key, header reservation, or floating panel.

### 4.2 Scaling and target law

The split, gutter, dock, scroll wells, and reading order remain stable at 100%,
125%, and 150% text. Copy wraps vertically, rows grow, and scroll extent changes.
Nothing clips, ellipsizes, horizontally scrolls, silently shrinks, or changes
macro topology.

Every interactive record, version, and action has a minimum 32-native-pixel
semantic body, exactly equivalent to the retained 64-logical-pixel archive
target. Four native pixels of detached Focus clearance are reserved separately
and never enlarge or create another semantic target.

Fractional placement, scaling, resampling, animated layout, container-remainder
distribution, and horizontal scrolling are forbidden.

habitat and Deep Navy controlled faces. Midnight uses Green-Black Glass habitat
and Blackened Verdigris controlled faces.

- index and dock are controlled dark;

> registered primitive → semantic role → Gallery component token
