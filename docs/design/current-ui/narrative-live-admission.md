# Narrative playback admission for current UI

Ordinary Hospital playback, semantic entries and endings now share one live-playback admission check. An accepted deferred layout occupies that admission before its first event; native cleanup keeps it occupied until the matching timeline ends. A restored checkpoint ID alone is metadata and does not imply live dialogue. Refusing an overlapping start preserves the standing runtime, layout, history and checkpoint context.

The retained runtime adapter tracks starting, live and stopping phases. The installed Dialogic handler supplies ephemeral generation-qualified start/end signals and a request identity on native starts. These distinguish an admitted request from a direct native replacement, including replacement with the same timeline path during startup. Late end notifications cannot complete a newer request. Existing unqualified addon signals and ordinary two-argument start callers remain supported. The request identity and generation are process-local and are never saved or used as gameplay completion identities.

Canceled pending layouts lose their queued start and clear callbacks, are removed from the active-layout lookup, and are deleted after their already-queued mount. This ordering both permits immediate retry and avoids a reproduced native access violation caused by marking the layout for deletion before its queued mount. Restoring a paused successor also invalidates the canceled event coroutine before unpausing, so rollback cannot execute old prose or mint a completion.

Failed startup restores the previous checkpoint cache and, for a staged restore, the previous pause state. Failure retires its owner record before notifying listeners. Ordinary physical commands receive a failure and can retry; semantic entries receive `entry_playback_failed` with their token and entry ID; endings retain their dedicated failure signal. Only matching natural completion reaches the existing completion ports. The ending path now forwards its actual label through the adapter instead of replacing it with event index zero.

This is the admission prerequisite tracked by `dwm-eei.19`, not completion of Pause or of the Witnessed UI family. The current branch has no production semantic completion-port binding or semantic failure-recovery listener; the new failure signal supplies that later integration seam without inventing a gameplay failure outcome. Full Pause still needs source-owner eligibility, suspension, Backup, Settings and coordinated return-to-title behavior. No save schema, gameplay outcome, accepted UI prose or visible layout is changed here.
